## Теоретическая часть

### 1. Уровни изоляции транзакций

Уровни изоляции определяют, как параллельные транзакции видят данные и взаимодействуют друг с другом. Основные уровни:

| Уровень         | Описание                                                                                                                |
| --------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Read Committed  | Уровень по умолчанию в PostgreSQL: видны только закоммиченные данные. Предотвращает грязное чтение.                     |
| Repeatable Read | Запрещает другим транзакциям изменять прочитанные данные до конца транзакции; в PostgreSQL реализован через снимок данных. |
| Serializable    | Полная изоляция. Эмулирует последовательное выполнение транзакций.                                                       |

В PostgreSQL уровень `Read Uncommitted` фактически работает как `Read Committed` — грязное чтение невозможно.

В EF Core уровень изоляции можно установить через `TransactionScope` или метод `BeginTransaction`:

```csharp
using var transaction = await context.Database.BeginTransactionAsync(System.Data.IsolationLevel.RepeatableRead);
```

### 2. Конкурентный доступ к данным

Конкурентный доступ возникает, когда несколько пользователей или процессов пытаются изменить одни и те же данные одновременно. Основные проблемы:

* **Грязное чтение** (Dirty Read)
* **Неповторяющееся чтение** (Non-Repeatable Read)
* **Фантомное чтение** (Phantom Read)

---

### 3. Оптимистическая блокировка

* Предполагает, что конфликты редки.
* Проверка изменений выполняется перед коммитом.
* В PostgreSQL в роли версии удобно использовать системный столбец `xmin` — идентификатор транзакции, последней изменившей строку. Он обновляется автоматически при каждом изменении строки.

Пример модели со свойством версии:

```csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }

    public uint Version { get; set; } // системный столбец xmin
}
```

Настройка токена конкурентности в Fluent API:

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Product>()
        .Property(p => p.Version)
        .IsRowVersion(); // Npgsql сопоставляет свойство с системным столбцом xmin
}
```

Обновление с проверкой версии:

```csharp
try
{
    product.Price = 2000;
    context.SaveChanges();
}
catch (DbUpdateConcurrencyException)
{
    Console.WriteLine("Конфликт обнаружен, повторите операцию.");
}
```

---

### 4. Пессимистическая блокировка

* Предполагает, что конфликты вероятны.
* Блокирует записи на время транзакции.
* В PostgreSQL запись блокируется запросом `SELECT ... FOR UPDATE` в рамках транзакции.
* В EF Core такого метода нет — запрос выполняется через `FromSqlRaw`.

Пример:

```csharp
using var transaction = await context.Database.BeginTransactionAsync();
var product = await context.Products
                           .FromSqlRaw("SELECT * FROM \"Products\" WHERE \"Id\" = {0} FOR UPDATE", 1)
                           .FirstOrDefaultAsync();
product.Price = 2500;
await context.SaveChangesAsync();
await transaction.CommitAsync();
```
