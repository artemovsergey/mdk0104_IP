##01::3
Что определяет архитектура приложения?
Структуру приложения, взаимодействие компонентов и способы масштабирования
Список установленных на сервере программ
Количество разработчиков в команде
Объём оперативной памяти сервера
##02::3
На что влияет выбор архитектуры приложения?
На масштабируемость, простоту разработки и поддержки, тестируемость и скорость развертывания
На разрядность операционной системы
На скорость интернет-соединения пользователя
На выбор браузера для работы с приложением
##03::3
Какая архитектура рекомендуется для малого проекта или MVP?
Монолит
Микросервисы
Модульный монолит с десятками модулей
Распределённая система с брокером событий
##04::3
Что относится к критериям выбора архитектуры для нового проекта?
Размер команды и навыки, ожидаемая нагрузка, требования к независимому развертыванию
Цвет интерфейса и логотип компании
Версия операционной системы на компьютере разработчика
Количество таблиц в базе данных
##05::3
Что представляет собой монолитная архитектура?
Все компоненты приложения объединены в один проект и развертываются вместе
Приложение разделено на независимые сервисы с отдельными базами данных
Каждый компонент общается с другими только по сети
Компоненты обмениваются событиями через брокер
##06::3
Какой плюс есть у монолитной архитектуры?
Простота разработки и развертывания, легко начать проект
Высокая масштабируемость отдельных компонентов
Гибкость в выборе технологий для каждого компонента
Полная изоляция модулей друг от друга
##07::3
Какой минус есть у монолитной архитектуры?
Любое изменение требует пересборки всего приложения
Каждый компонент нужно развертывать отдельно
Требуется обязательный брокер сообщений
Невозможно использовать базу данных
##08::3
Что представляет собой модульный монолит?
Единое развертывание приложения при логическом разделении на независимые модули
Набор отдельных приложений без общего развертывания
Систему, где каждый модуль является отдельным микросервисом
Приложение, разделённое только на слои базы данных
##09::3
Какие модули приведены в примере разделения на модули?
UserModule, OrderModule и ProductModule
AuthModule, CacheModule и LogModule
WebModule, DbModule и IoCModule
ClientModule, ServerModule и BotModule
##10::3
Какое преимущество есть у модульного монолита?
Проще тестировать отдельные модули и меньше проблем с развертыванием, чем у микросервисов
Независимое масштабирование каждого модуля
Полное отсутствие зависимостей между модулями
Отказ от единой сборки приложения
##11::3
Какой недостаток есть у модульного монолита?
Масштабирование ограничено единой сборкой, а зависимости между модулями нужно контролировать
Невозможность логического разделения кода
Обязательное использование Kubernetes
Каждый модуль требует собственной базы данных
##12::3
Что такое микросервисная архитектура?
Приложение состоит из небольших независимых сервисов, взаимодействующих через API или события
Все компоненты работают в одном процессе
Приложение разделено только на слои внутри одного проекта
Все сервисы объединены в одну сборку
##13::3
Что характерно для каждого микросервиса?
Собственная база данных и отдельное развертывание
Общая база данных со всеми остальными сервисами
Запуск внутри монолита
Отсутствие сетевого взаимодействия
##14::3
Как микросервисы взаимодействуют между собой?
Через REST, gRPC или брокеры событий RabbitMQ и Kafka
Через общие статические переменные
Через файлы конфигурации
Через общую папку на диске
##15::3
Как выглядит микросервис на .NET в примере лекции?
Отдельный проект ASP.NET Core Web API
Отдельный класс внутри монолита
Отдельная таблица в базе данных
Отдельный метод контроллера

##17::3
Какое преимущество дают микросервисы?
Независимое развертывание, масштабирование отдельных сервисов и гибкость в выборе технологий
Простая инфраструктура без дополнительных инструментов
Отсутствие необходимости в мониторинге и логировании
Единая кодовая база без сетевых вызовов
##18::3
Какой недостаток микросервисов указан в лекции?
Сложная инфраструктура, необходимость мониторинга и логирования, сложность отладки
Невозможность независимого развертывания
Низкая масштабируемость
Отсутствие поддержки API
##19::3
Какой архитектуре по таблице сравнения соответствуют высокая масштабируемость и низкая связность?

Монолиту

Классической двухуровневой архитектуре
##20::3
Что рекомендуется для среднего проекта с несколькими командами?
Модульный монолит
Микросервисы
Классический монолит
Одноуровневая архитектура
